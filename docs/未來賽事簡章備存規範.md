# 未來賽事簡章備存規範

未來賽事在有簡章或主辦方公告時，先建立可追溯的來源紀錄，再決定網站顯示哪些欄位。網站摘要不是完整資料庫；不顯示的資訊仍可保存在專案紀錄中，供日後補結果、校正與歷史查考。

## 收錄方式

- 每項來源建立一份 `docs/` 登錄紀錄，寫明文件名稱、來源類型、核對日期，以及可辨認的版本或公告差異。
- 盡量保存正式賽名、指導／主辦／執行單位、日期與地點、辯題及其來源、參賽資格、隊數上限、賽制、報名期間、費用與保證金、獎項規劃、重要規則及尚待確認事項。
- `data/event-metadata.csv` 收錄適合跨賽事查詢的基本資料。隊數上限只代表簡章規劃，不等於錄取或實際參賽隊伍。
- `data/upcoming-events.js` 僅收錄網站時間軸／未來賽事詳情需要展示的內容；未確認的辯題留白並在來源紀錄說明，不得以關聯賽事的題目代填。
- 未來收到新版本時，記錄版本差異與採用依據，不以新文件覆蓋舊來源事實。賽後再將公告賽果與簡章規劃分開記錄。
- 聯絡人私人電話、個人聯絡資料不複製到公開網站摘要；備存時也以職務聯絡管道或來源位置為主，除非歷史查考確有必要。

## 公開與備存的界線

登錄紀錄提供研究與維護者查考，網站只公開適合一般訪客使用的賽名、日期、地點、已確認辯題及必要主辦資訊。新增網站欄位前先確認其展示價值；不要為了保存而一律放進前台，也不要把「前台不顯示」誤當作「來源可丟棄」。
