# Cardano 上鏈可行性研究

研究日期：2026-09-21。對象：台灣高中辯論公開網。這是研究與預算估算，尚未建立錢包、購買 ADA、上傳資料、送出交易或修改網站功能。

## 結論

Cardano 可以達成「保留歷史、發布更正、驗證資料未被偷改」，不能提供「把公鏈上的歷史原文徹底刪掉」。

對本專案最合適的起點是：既有 CSV、Git 與靜態網站繼續運作，另以 Cardano Preprod 測試網存放公開版本的雜湊指紋，使用者閱讀網站不必連錢包。不要先把學生姓名、裁判評語、私人裁單全部公開上鏈，也不需要先發 NFT 或寫智能合約。

若目標只是資料備份、可修改與維護紀錄，目前的 Git 已能解決大部分需求。上鏈新增的價值是：讓外部使用者能比對一個由指定發布者承諾、且無法由網站管理員單方面重寫的歷史版本。它不會證明賽果本身正確，也不會自動讓網站更快。

## 目前規模與資料邊界

依正式工作區讀取，而非推測：

- 33 個賽事、1,073 場戰績、281 筆榮譽、271 個學校／隊伍單位、4 筆登場紀錄、38 筆辯題。
- `data/public-data.js`：786,762 bytes；將其資料轉成無縮排 JSON：497,453 bytes；該 JSON 使用 gzip 壓縮後：51,940 bytes。
- `public-data*.csv` 合計 188,447 bytes，但不包含全部名冊、網站介紹等資料，不能當成全站完整備份大小。
- 目前首頁執行所需的 HTML、JS、CSS、公開資料與 WebP／Logo 合計約 1.08 MB；原始 PNG 額外約 1.94 MB。這不包含 Git 歷史、研究文件及所有來源備份。
- 個人及隊伍建檔在訪客自己的 localStorage，不在公開資料檔中；管理者不能直接把所有訪客的私人紀錄一併搬走。若新增同步，涉及新的告知、權限、授權、匯出及刪除設計。
- 賽程照片、圖片、文件可能包含其他人的個資或著作；取得檔案與獲得永久公開散布權是不同問題。

## 三種路線

| 路線 | 鏈上內容 | 修正方式 | 工程難度（1 最低、5 最高） | 適用性 |
| --- | --- | --- | --- | --- |
| 版本指紋存證 | 雜湊、版本、前版交易參照、必要的發布資訊 | 原資料修正後發新指紋 | 試驗 2；正式維護 3 | 推薦 |
| 公開資料全文分批寫入交易 metadata | JSON／CBOR／壓縮資料及分段索引 | 新增完整版本或更正紀錄，舊全文仍可查 | 3–4 | 真的需要鏈上重建資料時再考慮 |
| 智能合約管理有效狀態與修改權限 | datum、管理權限、狀態／版本參照 | 消耗舊 UTxO、產生新 UTxO；歷史仍存在 | 4–5 | 多主辦單位共同維護、需要鏈上強制規則才考慮 |

「指紋存證」不能宣稱為「所有資料全文已上鏈」。指紋無法還原遺失原檔，仍須保留備份。鏈上存 IPFS CID 也不等於把全文存進 Cardano。

Cardano 原生支援交易 metadata，單純存證不需要 NFT、代幣或智能合約。Metadata 並非合約可以直接讀取、修改的一般資料庫；若要合約強制更新規則，須另外設計 datum／UTxO 等結構。[1][2][3]

## 可修正到底代表什麼

例如版本 1 把比分寫成 3：0，之後確認應是 2：1：

1. 在原 CSV 更正比分、記錄原因並提交 Git。
2. 產生版本 2 的資料快照及指紋。
3. 由授權發布者簽署新交易，連到版本 1 的交易。
4. 網站顯示版本 2，另標示舊版已被更正。

這是「新版本取代有效狀態」，不是修改舊交易。網站可以停止顯示一個版本，但無法阻止第三方讀取已公開的鏈上原文。智能合約升級或更新 datum 也不會消除歷史。[1][4]

必須設計：可信任的初始發布金鑰、授權金鑰輪替、版本順序、重複發布／分叉處理、撤回與恢復程序。不能只搜尋 metadata 中名字相同且時間最新的交易，否則任何人都能冒名發一份。

「停止使用」也要可行：關掉鏈上驗證入口後，網站仍可從 CSV／產生資料正常運作，管理者仍能匯出 CSV、JSON；已送出的鏈上紀錄則留在原處。測試網不是秘密空間，也不能保證第三方未保存測試資料。

## 費用：先看 ADA，再看工程

### 可核對的鏈上參數

研究當日透過 Koios 主網唯讀 API 取得：`txFeePerByte=44`、`txFeeFixed=155381`（lovelace）、`maxTxSize=16384` bytes、`utxoCostPerByte=4310`。與 Cardano 官方費用說明交叉比對。這些是可治理調整的參數，實作時要重查，不能永久寫死。[5][6]

不使用 Plutus 的普通交易最低費用模型：

`費用 ADA = (155381 + 44 × 完整序列化交易位元組數) / 1,000,000`

完整交易 1,000 bytes 約 0.199381 ADA，2,000 bytes 約 0.243381 ADA，16,000 bytes 約 0.859381 ADA。這是整筆交易大小，不是只算資料文字。智能合約另有執行等費用。

16,384 bytes 是整筆交易限制，不是可以全部拿來裝資料。Metadata 的單一文字或位元組字串有 64 bytes 限制；中文須按 UTF-8 bytes 處理，而非字數，長內容須分段。[2][6]

### 套入本網站的規劃區間

下表是設計預算，不是已建立及簽署交易的報價；假設少量輸入／輸出、單一發布者、普通 metadata 交易。

| 情境 | 預估主網交易費 | 說明 |
| --- | --- | --- |
| 全站一個版本指紋 | 0.2–0.35 ADA／次 | 多個檔案先做清單，再承諾清單指紋即可 |
| 每個賽事各一筆，共 33 筆 | 6.6–11.55 ADA／輪 | 只是可選粒度，不需要每次全重發 |
| 1,073 場各自一筆 | 約 215–376 ADA／輪 | 尚不含榮譽等；固定交易費累積，不推薦 |
| 約 497 KB 精簡 JSON 全文分批 | 約 30–50 ADA／版 | 試算約 34 筆；需加入分段與版本資訊 |
| 約 52 KB gzip JSON 全文分批 | 約 4–8 ADA／版 | 試算約 4 筆，需解壓、排序、完整性驗證與版本規格 |
| 把原 1.94 MB PNG 也分批上鏈 | 額外約 110–150 ADA／份 | 不包含其他檔案；證明或指紋通常更合適 |

全文試算的方法：每筆預留 15,000 bytes 原始載荷、每 64 bytes 增加約 2 bytes 分段編碼、每筆先估 500 bytes 交易骨架。套入公式，精簡 JSON 約 28.60 ADA、gzip 約 3.07 ADA，再留格式／索引／交易大小差異的預算。尚未實作 CBOR 與實際交易建立，因此最終費用須以工具計算為準。若採較低效的字串編碼、更多簽名或更多 UTxO，費用可能超出表格。

不要每次按下儲存就上鏈：若每天發布一次小指紋，一個月約 6–10.5 ADA，一年約 73–128 ADA。先批次確認再發布即可降低交易數。

台幣換算請用實際買入成本：`ADA 數量 × 當時每 ADA 的台幣價格`。例如**純假設** 1 ADA=NT$20，0.3 ADA 約 NT$6、50 ADA 約 NT$1,000；這不是即時行情，也不含交易所手續費、價差、提領費或稅務成本。

### 不是交易費的其他成本

- **測試網：** Preprod／Preview 的 tADA 沒有貨幣價值，可由 faucet 免費取得；可將試驗的真 ADA 支出設為 0。[7]
- **最低 ADA 餘額：** 每個 UTxO 輸出須帶足夠 ADA。它通常仍是自己控制的資金，不是燒掉的手續費。若只用 metadata 並把找零回到自己的錢包，可重複使用，不必為每一筆歷史紀錄永遠鎖一份 ADA。若大量資料放 inline datum，會增加最低 ADA 要求。[8][9]
- **API／節點：** 可先用託管 API 的免費方案，不必自己運行完整節點。Blockfrost 官方指南確認有免費層；本次未取得可靠的即時付費價目，故不虛報固定月費。早期可先預留 NT$0–1,500／月做 API、備份與選用儲存的規劃額度，超量依實際方案調整，這不是供應商報價。[10]
- **原檔儲存：** Git／一般備份可先沿用。IPFS 並非上傳後保證永久存在，仍需 pinning、備援與持續營運；資料可能被他人另行保存，取消自己的 pin 不等於全球刪除。[11]
- **簽章設備與人工：** 主網可考慮硬體錢包；另計金鑰備份、發布覆核、錯誤處理、依賴升級，以及必要的法律／資安審查。第一版不用高價合約稽核替代真正需要的流程設計；若日後上智能合約則須另評估專業稽核。[12]

## 難度、工時與開發費

以下是基於目前純前端＋Python資料管線的工程估算，不是廠商市場報價。假設熟悉網站與 Cardano 的一名工程人員，一人日 8 小時；不含資料使用權確認、等待使用者測試、法律審查、第三方合約稽核。

| 範圍 | 人日估算 | 用 NT$1,500／小時作為假設換算 |
| --- | --- | --- |
| Preprod 指紋試驗，含一次更正、驗證與停用 | 2–5 人日 | NT$24,000–60,000 |
| 可長期維護的主網存證，含安全發布、重試、文件、金鑰更換流程 | 5–15 人日 | NT$60,000–180,000 |
| 全文分段存鏈、重建、版本索引與更正機制 | 15–30 人日 | NT$180,000–360,000 |
| 合約管理修改權限、多方核准、升級／遷移 | 30–60+ 人日 | NT$360,000–720,000+ |

各列是不同範圍的總體級距，不應直接相加。若自己搭配 AI 完成，未必支付上述外包費，但仍有帳號／工具費、自己的時間，以及人工驗證與簽章責任；不能把 AI 生成速度當成已完成安全審查。缺乏工程背景而獨自處理金鑰與異常交易，難度會高於表中工程人員估算。

## 主要風險與應對

| 風險 | 對本站的實際影響 | 建議 |
| --- | --- | --- |
| 學生個資長期曝光 | 姓名、學校、成績可連結到個人，可能涉及未成年人 | 第一階段不放真實個人原文，先用合成資料；正式資料逐項確認依據 |
| 更正／刪除請求 | 網站下架不能刪掉公鏈副本 | 個人資料留鏈外，訂出更正、爭議與下架政策 |
| 金鑰遺失／被盜 | 無法繼續授權，或攻擊者冒名發布 | 測試錢包與主網隔離、人工簽署、備份及可驗證輪替；不把助記詞放 Git、前端或聊天 |
| 指紋被誤當內容真實保證 | 錯誤賽果也可以有完全有效的存證 | 顯示「版本完整性已驗證」，另標資料來源與查證狀態 |
| 指紋不等於匿名 | 小範圍姓名／比分可能被猜測後比對；鏈上關聯永久存在 | 不逐一雜湊姓名冒充去識別化；依威脅模型採批次承諾或隨機化承諾 |
| 編碼與自動生成時間 | 同份語意資料可能因排序、換行或 generatedAt 改變指紋 | 保存精確發布檔；固定 UTF-8／排序／schema；把運行時間與內容版本分開 |
| 網路、索引服務故障 | 若每次開頁都等鏈上查詢，會比現在更慢 | 靜態頁面照常載入，驗證按需執行；索引可重建、API 可替換 |
| 交易未確認、短期回滾、重試重複 | 網站錯誤宣稱已存證，或重送扣費 | 區分待送／已送／已確認；依交易ID追蹤、確認深度與重試策略 |
| 多個維護者同時更正 | 出現不同有效版本或找零UTxO衝突 | 第一版單一發布流程與明確前版引用，之後再擴充共同治理 |
| 智能合約缺陷 | 可能鎖住狀態或權限；修正成本高 | 單純存證不用合約；必要時先寫權限／遷移規格及測試 |

台灣個資法第 3、5、11、19、20 條涉及當事人權利、目的必要性、更正、停止利用／刪除，以及非公務機關蒐集利用的條件。「曾公開的賽果」不能直接推論為「任何形式的永久再散布都沒問題」。涉及真實學生資料的正式方案應請熟悉個資的法律專業者確認；這是設計風險分析，不是對本案合法性的結論。法規頁也標示部分新修條文尚未施行，本研究不把尚未施行的新條文當成已生效義務。[13]

## 建議的最小試驗

1. 維持正式網站不變，在現有專案另加可關閉的試驗入口；只選一份合成或經篩選的示範賽事。
2. 明訂承諾範圍：公開賽事資料，不含訪客 localStorage、來源照片或私人裁判評語。
3. 使用 Preprod 獨立錢包與免費 tADA；建立第一份資料檔、指紋與簽署交易。
4. 增加「驗證本版本」功能：比對檔案、鏈上雜湊及已知發布者；一般訪客不必安裝錢包。
5. 改一次比分，發布新版並連到舊版；顯示新舊差異及更正原因，原因不得含多餘個資。
6. 驗收：改動一個字即驗證失敗；陌生金鑰的冒名版本被拒；更正只由授權者認可；API 故障時網站仍可讀；移除試驗功能後資料仍可匯出及繼續維護。
7. 再決定是否進主網。預先設定第一次主網存證費上限，不自動把測試資料整批搬上主網。

可沿用 `tools/build_data.py` 的輸出流程，但存證應是獨立的發布步驟，不能每次更新網站就自動花 ADA。現在的比賽ID包含內容雜湊，修正內容會換ID；若未來要逐場鏈上更正，需另外設置不隨比分變動的永久比賽ID。第一版以整份版本快照存證，可先避免逐筆資料模型遷移。
