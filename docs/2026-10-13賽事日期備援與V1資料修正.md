# 賽事日期備援與 V1 公開資料修正

## 目標

- 修正「逐場戰績或榮譽已有完整日期，但賽事整體日期仍空白」的落差。
- 只修改公開網站與它產生的公開 V1 靜態資料，不修改 `opendebate-ios-app` 程式。
- 保留主辦方明載的完整賽期，不用目前收錄的少數場次把它縮短。

## 規則

1. `data/event-metadata.csv` 明載的開始／結束日期永遠優先。
2. 任一端留白時，才以同賽事已收錄戰績與榮譽的完整 `YYYY-MM-DD` 日期補值：開始取最早日，結束取最晚日。
3. 備援日期只寫入 `data/public-data.js` 與 `data/ios/v1/` 生成資料，不反寫來源 CSV。
4. 使用備援日期的賽事頁顯示「日期依已收錄戰績／榮譽整理」，避免把推定範圍誤認為主辦方公告。
5. 明載日期範圍若排除任何已收錄場次或榮譽日期，預檢直接停止。
6. 只有年份、空白或不完整日期不參與推定；整體賽期也不會反向填入逐場資料。

## 影響範圍

- 公開網站歷史賽事詳情頁會取得較完整的日期範圍。
- `data/ios/v1/catalog.json` 會隨同一公開建置流程更新，因此既有 App 下載公開資料後能取得日期；App 原始碼與專案設定不變。
- 首頁「未來賽事」分類仍以 `data/upcoming-events.js` 為準，不會因這次補歷史資料日期而提前或延後換軌。

## 驗收單

- [x] 主辦方明載且較寬的賽期維持原值。
